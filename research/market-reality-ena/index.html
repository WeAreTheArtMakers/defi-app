ENA on Ethereum: how much real on-chain market is there?

Exchange listings, dashboards and token pages show a volume number. This page asks what stands behind it for ENA (Ethena) on Ethereum: how much can actually be sold or bought before the price moves, how much of the trading looks independent, who provides the liquidity, and how much of it we can verify. Everything comes from public chain data and every number can be re-derived.

Why ENA

ENA is a large token with a known team (Ethena Labs), real activity and liquidity spread over several venues on Ethereum: Uniswap v3 and v4, PancakeSwap v3, smaller concentrated-liquidity forks and one venue we do not decode. Our pipeline already collects its main pools, so this page can show both what we verify today and what is still missing. We have no relationship with Ethena Labs.

This week was not ordinary. On 29–30 Oct an address that had received ENA from the wallet labelled “Binance 14” sold it into Uniswap pools (documented block by block in our 29 Oct research page). Those two days carry 94% of the week's ENA volume, so where it matters we also give the numbers for the other five days.

Every section answers five questions: what was observed, where the evidence is, how it was computed, how far it can be trusted, and how to check it yourself.

2. Liquidity depth

Observed
Selling 516,045 ENA moves the exit pools −2%; 1.28 M moves them −5%, 2.52 M −10%. Buying side: 521,916 / 1.31 M / 2.51 M ENA for +2 / +5 / +10%. One pool, ENA/WETH 0.3%, holds 96% of the −2% depth.
Evidence
Pool state at block 26,318,400 (01 Nov 2026, 07:23 UTC): slot0, liquidity, tickBitmap and ticks (v3-style pools), the same through Uniswap's StateView contract for v4 pools, getReserves for v2 pools. Only pools quoted in ETH/WETH, USDC or USDT count as exit depth.
Method
Concentrated liquidity is walked tick by tick: between two initialized ticks the pool behaves like x·y = L² (amount of token0 = L·(1/√Plow − 1/√Phigh)), and crossing a tick adds or removes its liquidityNet. The LP fee is added to the input. Routing assumption: the order is split so that every exit pool ends at the same relative price move (what arbitrage would enforce); real routers split less well, so a single-pool sale moves the price more.
Trust
Independent check: Uniswap's QuoterV2 contract simulated the same sales against the live pool code at the same block — see the table below. Depth is a snapshot: liquidity providers can add or withdraw at any time. sENA pools (4.14 M ENA at −2%) are shown but not counted, since sENA is a staking receipt of ENA itself.

Check it yourself: check_depth.py (no dependencies, any Ethereum node) 
"""Standalone check (no dependencies): how much ENA moves the Uniswap v3 ENA/WETH 0.3 % pool price by -2 / -5 / -10 %.

Reads slot0, liquidity, the tick bitmap and every initialized tick within ±1,300 ticks at one block, walks the price
down tick by tick (constant-liquidity math between ticks), then asks Uniswap's QuoterV2 to simulate the -2 % sale.
Usage: python3 check_depth.py [block]
"""
import json
import sys
import urllib.request

RPC = "https://gateway.tenderly.co/public/mainnet"       # any Ethereum node that serves state at the block
POOL = "0xc3db44adc1fcdfd5671f555236eae49f4a8eea18"      # ENA (token0, 18 dec) / WETH (token1, 18 dec), fee 0.3 %, spacing 60
QUOTER = "0x61ffe014ba17989e743c5f6cb21bf9697530b21e"    # Uniswap QuoterV2
ENA, WETH = "57e114b691db790c35207b2e685d4a43181e6061", "c02aaa39b223fe8d0a0e5c4f27ead9083c756cc2"
BLOCK = hex(int(sys.argv[1]) if len(sys.argv) > 1 else 26318400)
op = urllib.request.build_opener(urllib.request.ProxyHandler({}))


def call(to, data):
    body = json.dumps({"jsonrpc": "2.0", "id": 1, "method": "eth_call", "params": [{"to": to, "data": data}, BLOCK]}).encode()
    req = urllib.request.Request(RPC, body, {"Content-Type": "application/json", "User-Agent": "check"})
    return json.load(op.open(req, timeout=60))["result"]


def word(h, i, signed=False):
    v = int(h[2 + 64 * i:2 + 64 * (i + 1)], 16)
    return v - (1 << 256) if signed and v >= 1 << 255 else v


def enc(v):
    return format(v % (1 << 256), "064x")


slot0 = call(POOL, "0x3850c7bd")
s, tick = word(slot0, 0) / 2 ** 96, word(slot0, 1, True)
L = word(call(POOL, "0x1a686502"), 0)
ticks = {}
for w in range(((tick - 1300) // 60) >> 8, (((tick + 1300) // 60) >> 8) + 1):
    bm = word(call(POOL, "0x5339c296" + enc(w)), 0)                     # tickBitmap(int16)
    for bit in range(256):
        t = (w * 256 + bit) * 60
        if bm >> bit & 1 and t <= tick and tick - t <= 1300:
            ticks[t] = word(call(POOL, "0xf30dba93" + enc(t)), 1, True)  # ticks(int24) -> liquidityNet
for level in (0.02, 0.05, 0.10):
    target, cur, liq, ena_in, weth_out = s * (1 - level) ** 0.5, s, L, 0.0, 0.0
    for t in sorted(ticks, reverse=True):                               # cross initialized ticks downwards
        st = 1.0001 ** (t / 2)
        if st <= target:
            break
        ena_in += liq * (1 / st - 1 / cur); weth_out += liq * (cur - st); cur = st; liq -= ticks[t]
    ena_in += liq * (1 / target - 1 / cur); weth_out += liq * (cur - target)
    gross = ena_in / 0.997                                              # the 0.3 % LP fee is charged on the input
    print(f"-{level:.0%}: sell {gross / 1e18:,.0f} ENA -> {weth_out / 1e18:,.4f} WETH")
    if level == 0.02:
        q = call(QUOTER, "0xc6a5026a" + enc(int(ENA, 16)) + enc(int(WETH, 16)) + enc(int(gross)) + enc(3000) + enc(0))
        moved = (word(q, 1) / 2 ** 96) ** 2 / s ** 2 - 1
        print(f"   QuoterV2: {word(q, 0) / 1e18:,.4f} WETH out, pool price after {moved:+.3%}")

3. Organic vs. inflated activity

Observed
1,948 distinct traders made 14,975 swaps (850.86 M ENA gross). The top 10 addresses account for 67.8% of the volume, the largest alone for 25.6%. Our organic estimate is 73.2% of gross volume (60.6% if bot-like cadence is also removed). The week is two different markets: on 29–30 Oct, 94% of the week's volume traded in two days; on the other five days, 49.88 M ENA traded, 97% passed the exclusion rules, but only 14% came from addresses without a bot-like cadence and the top 10 addresses made 91% of it.
Evidence
Every Swap log of the decoded pools in the window and the receipt of each of its 10,823 transactions (sender, called contract, ENA Transfer logs).
Method
Trader = the address whose ENA balance went down (sale) or up (purchase) in that transaction's ENA Transfer logs, never a pool, router or settlement contract; if none qualifies, the transaction sender (tx.from). This is the same rule as our live trader attribution. We do not use the Swap event's sender/recipient, which are usually routers (604 distinct recipients vs 2,342 distinct transaction senders). 87% of swaps were attributed from Transfer logs.
Trust
Patterns are measured, not intent: a wash-like round trip can be a market maker rebalancing, a sandwich-shaped sequence can be coincidence. We exclude only clear shapes, so the organic share is an upper bound: genuinely independent demand can only be lower.
Check it
Swap logs + receipts from any node; the rules are fixed numbers listed below (methodology market-reality/0.1).

Rules (all conservative: a swap is excluded only when the shape is clear)

  • Same-transaction round trip (excluded, 225.74 M ENA): one transaction swaps ENA in two or more pools in opposite directions and its net ENA is within 1% of the gross — arbitrage between ENA pools or a route that passes through ENA. 710 transactions.
  • Same-block sandwich (excluded, 569,838 ENA): in one block and pool, the same actor (the contract it calls, or its sender) trades before and after another trader's swap in the same direction, the back leg within 20% of the front leg's size. Only the two outer legs are excluded; the trade in the middle is real demand. 14 found.
  • Wash-like round trip (excluded, 2.13 M ENA): one trader buys and sells with no more than 25 blocks (~5 minutes) between consecutive swaps, and the run's net ENA is within 2% of its gross. 24 runs by 21 traders.
  • Bot-like cadence (flagged, removed only in the strict estimate, 217.03 M ENA by 23 traders): ≥ 50 swaps in 7 days, or ≥ 20 swaps at a regular rhythm (coefficient of variation of the block gaps < 0.5). Arbitrage and market-making bots keep pools in line with other markets, so they are not counted as fake.

5. Hook and pool risk (Uniswap v4)

Observed
222 Uniswap v4 pools pair ENA with another token; 48 of them had swaps in the window (4.3% of the volume). 20 pools use a hook with permission bits set, 16 of them with a swap ReturnDelta bit. None of the hooked pools had a swap in the window: all v4 trading in ENA went through hookless pools (hook address 0x0, no permission bits).
Evidence
The pools' Initialize logs on the PoolManager (0x0000…8a90), which carry the full PoolKey (currencies, fee, tick spacing, hook address); every key was re-hashed to its PoolId.
Method
In Uniswap v4 a hook's permissions are fixed by its address: the lowest 14 bits of the hook address say which callbacks the PoolManager will call. We read those bits; we do not audit the hook's code.
Trust
Exact for the permission set (the PoolManager enforces it). What an enabled hook actually does needs a code review. Many of these pools pair ENA with tokens that have no other market (Pendle SY/PT wrappers, launch tokens); they hold no or little liquidity.

BitPermissionWhat it allows the hook to do

5beforeDonateruns code before a donation to liquidity providers

3beforeSwapReturnDeltacan take or give tokens in a swap, so the Swap event no longer shows what the trader settled

1afterAddLiquidityReturnDeltacan change what a liquidity provider pays on deposit
0afterRemoveLiquidityReturnDeltacan change what a liquidity provider receives on withdrawal

The two …ReturnDelta swap bits matter most for data quality: with them, the Swap event no longer equals what the trader paid or received, so volume read from events can be wrong. None of the ENA pools that traded this week has a hook at all.

What this does and does not say

  • It describes on-chain DEX markets on Ethereum only. Centralized exchanges, other chains and OTC trading are outside this view, and for a large token they can be bigger than everything here.
  • Depth is a snapshot of one block. Concentrated liquidity can be added or removed in a single transaction.
  • “Organic”, “wash-like”, “sandwich” and “bot-like” are pattern labels from fixed rules, not findings about intent or wrongdoing. A different threshold gives a different number; the rules and thresholds are on this page.
  • An address is not a person: one trader can use several addresses, and a contract (vault, smart wallet, settlement) can stand for many users.
  • Pool discovery relies on creation events that name the token. Pools created by unusual factories, or vaults that do not index token addresses, can be missing; the venue we cannot decode is shown with an upper-bound estimate.
  • Amounts are token units; quote-side amounts are in the pool's own quote token (WETH, USDC, USDT). We do not convert to USD.
